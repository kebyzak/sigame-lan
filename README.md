# СИ-Игра (LAN)

Локальная многопользовательская «Своя игра» в духе [SIGame](https://sigame.vladimirkhil.com/): ноутбук ведущего — сервер, игроки подключаются с телефонов по Wi-Fi. Без регистрации, облака и интернета.

## Быстрый старт

Нужен **Node.js 20+**.

```bash
npm install
npm run start:lan
```

В консоли появятся адреса и QR-код:

```
  Ведущий:  http://localhost:3000/host
  Игроки:   http://192.168.1.23:3000/   (wlan0)
```

1. Откройте на ноутбуке **http://localhost:3000** — это панель ведущего.
2. Перетащите файл `.siq` в блок «Пакет вопросов».
3. Игроки сканируют QR-код (он есть и в консоли, и в панели ведущего), вводят имя.
4. Нажмите «Начать игру».

Повторный запуск без пересборки: `npm start`.

### Экран для ТВ

`http://<ip>:3000/screen` — табло и вопросы для общего экрана/проектора, **без ответов** (в отличие от панели ведущего). Кнопка «Экран» в панели ведущего открывает его в новой вкладке.

### Ведущий с другого устройства

Панель ведущего выдаёт ключ только на самом компьютере-сервере. Для планшета используйте ссылку `http://<ip>:3000/host?key=…` из консоли — не показывайте её игрокам.

## Как играть

| Ведущий | Игроки |
|---|---|
| Выбирает вопрос на табло | Видят вопрос на телефоне |
| Кнопка открывается сама (см. «Авто-кнопка» ниже) или сразу — **Пробел** | Жмут большую кнопку — побеждает первый нажавший по данным сервера |
| Слушает ответ, отмечает **Y** (верно) / **N** (неверно) | Видят, кто отвечает, и результат |
| После ошибки — «Открыть кнопку снова» | Ответивший неверно больше не может нажать |
| | Нажал до открытия — **фальстарт**: кнопка блокируется на 1 сек, повторные нажатия продлевают блокировку |
| «Показать ответ» / «Пропустить» | Правильный ответ всегда показывается всем перед возвратом к табло и остаётся на табло до следующего вопроса |
| **A** — показать ответ, **→** — к табло | |

Ведущий в любой момент может: изменить счёт (клик по числу или ±), назначить отвечающего вручную (🎤), назначить выбирающего (👑), пропустить или вернуть вопрос, сменить раунд, поставить паузу, удалить игрока, завершить игру.

### Авто-кнопка

После показа обычного вопроса сервер сам открывает кнопку для всех одновременно:

- **Текст** — по времени чтения (~200 слов/мин, плюс варианты ответа): от 1,5 до 12 сек.
- **Картинка, аудио, видео** (в том числе вместе с текстом) — случайно 3–7 сек, задержка генерируется один раз на сервере. Для аудио/видео отсчёт начинается, когда звук реально заиграл у ведущего (если ведущий без звука — через 4 сек после показа).

Игроки не видят отсчёта: до активации кнопка серая, при активации — вспышка, короткий сигнал и вибрация. Нажатия до активации не засчитываются (это фальстарт). Ведущий видит отсчёт в блоке «Кнопка», может открыть сразу (**Пробел**), закрыть/отменить, а переключатель «⚡ Авто-кнопка» в верхней панели выключает автоматику. Пауза замораживает отсчёт; обновление страницы или перезапуск сервера его не сбрасывают. Параметры — в `src/server/game/autoBuzzer.ts`.

### Поддержка типов вопросов SIGame

| Тип в пакете | Как играется |
|---|---|
| Обычный (`simple`) | Кнопка, ±стоимость |
| Аукцион (`stake`, v4 `auction`) | Ведущий указывает победителя торгов и ставку (есть «Ва-банк») |
| Кот в мешке (`secret`, `secretPublicPrice`, v4 `cat`/`bagcat`) | Ведущий выбирает, кому передан вопрос, и стоимость из пакета |
| Кот без вопроса (`secretNoQuestion`) | Очки начисляются сразу |
| Без риска (`noRisk`, v4 `sponsored`) | Стоимость ×2, за ошибку не штрафуется |
| Для всех (`forAll`) | Все пишут ответ с телефона, ведущий проверяет каждый |
| Финал / ставки (`stakeAll`, раунд `type="final"`) | Ведущий убирает темы → игроки ставят (до своего счёта) → пишут ответ → ведущий проверяет |
| Выбор варианта (`answerType=select`) | Варианты A/B/C показываются всем, правильный подсвечивается при раскрытии |

Медиа: изображения, аудио (играет на компьютере ведущего; на телефоне — по кнопке 🔇/🔊), видео, HTML (в изолированном iframe). Отсутствующие файлы не ломают игру — показывается пометка и предупреждение при импорте.

## Устройство

```
src/
  shared/types.ts          общие типы и протокол клиента/сервера
  server/
    index.ts               Express + Socket.IO, загрузка, раздача медиа, запуск
    siq/zip.ts             безопасное чтение ZIP (лимиты, защита от ZIP-бомб)
    siq/parser.ts          парсер content.xml (форматы v5 <params>/<item> и v4 <scenario>/<atom>)
    game/engine.ts         игровая логика: кнопка, счёт, этапы вопроса, представления для ролей
    game/state.ts          сохраняемое состояние
    store.ts               хранение в ./data (состояние, ключ ведущего, пакеты)
    net.ts                 определение LAN-адреса
  client/                  React + Vite + Tailwind
    pages/HostPage.tsx     панель ведущего
    pages/PlayerPage.tsx   телефон игрока
    pages/ScreenPage.tsx   экран для ТВ
scripts/smoke-test.mjs     сквозной тест
```

**Синхронизация.** Сервер — единственный источник истины. После каждого изменения каждому подключению отправляется своё представление состояния (`Game.view`): ведущий получает ответы, игроки и ТВ — только раскрытое.

**Кнопка.** Нажатия обрабатываются в порядке поступления на сервер (Node.js однопоточный): первое валидное нажатие при открытой кнопке побеждает и тут же закрывает её; повторные, ранние и заблокированные нажатия игнорируются. Время клиента не используется. Транспорт — только WebSocket, нажатие отправляется по `pointerdown`.

**Сохранение.** Состояние пишется в `data/state.json` (атомарно, с задержкой 250 мс) — перезапуск сервера, обновление страницы ведущего или игрока не сбрасывают игру. Игроки восстанавливаются по токену в `localStorage`. Чтобы начать с чистого листа, остановите сервер и удалите папку `data/`.

## Безопасность

- Действия ведущего проверяются на сервере по ключу; ключ выдаётся только запросам с `localhost` и никогда не попадает в QR-код.
- Ответы, медиа ответов, письменные ответы и ставки соперников не отправляются игрокам до раскрытия. Медиа доступны по случайным неугадываемым id.
- Загрузка: лимит 500 МБ (`MAX_UPLOAD_MB`), лимиты на число файлов, распакованный размер и степень сжатия (ZIP-бомбы), отказ от `DOCTYPE/ENTITY` в XML. Файлы из архива сохраняются под сгенерированными именами — пути из архива никогда не используются как пути на диске.
- Медиа отдаются с `X-Content-Type-Options: nosniff` и CSP `sandbox`.

## Настройки

| Переменная | По умолчанию | |
|---|---|---|
| `PORT` | `3000` | порт |
| `HOST` | `0.0.0.0` | адрес привязки |
| `MAX_UPLOAD_MB` | `500` | максимальный размер пакета |
| `FALSE_START_MS` | `1000` | блокировка за фальстарт (нажатие до открытия кнопки); каждое нажатие во время блокировки продлевает её (`0` — без фальстартов) |
| `DATA_DIR` | `./data` | где хранить состояние и пакеты |

## Тесты

```bash
npm run build
node scripts/smoke-test.mjs path/to/package.siq
```

Запускает сервер на временной папке и проверяет: импорт реального пакета, вход 5 игроков, синхронизацию, одновременные нажатия (ровно один победитель), блокировку после ошибки, счёт, скрытие ответов от игроков, переподключение без дублей, перезапуск сервера с сохранением, финал со ставками, отказ от ZIP-бомбы/`../`/`DOCTYPE`, запрет действий ведущего для игроков.

## Разработка

```bash
npm run dev:server   # сервер на :3000 с перезапуском
npm run dev:client   # Vite на :5173 с прокси на сервер
```

## Если не подключается

- Телефоны и ноутбук должны быть в одной сети Wi-Fi (гостевые сети часто изолируют устройства).
- Разрешите входящие подключения к Node.js в брандмауэре (Windows спросит при первом запуске; Linux: `sudo ufw allow 3000/tcp`).
- Если адресов несколько (VPN, Docker), выберите нужный под QR-кодом.
- Нужен современный браузер: iOS 16.4+, Chrome/Android 111+.
